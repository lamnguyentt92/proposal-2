# Verification of the citations in the cross-family reviews of Proposal 2 (2026-11-20)

Scope: every work cited in `XMODEL_NOVELTY_P2_RESPONSE.md` and `XMODEL_REDTEAM_P2_RESPONSE.md` was looked up in a primary record in this session (arXiv API on export.arxiv.org, alphaXiv full-text reader, ACL Anthology page and PDF, Crossref API, publisher or author-hosted PDF, icml.cc). The reviews' own citation links (several point to mirror domains such as `arxiv.cnoctave.top`, `sex8x8.com`, `borowiecki.dev`) were ignored. This file checks descriptions of the cited works only. It does not judge the proposal or the reviews' arguments.

Result in one line: all 18 records exist and none is fabricated. 17 descriptions are accurate; one title is out of date (item 11, red-team review only). Several accurate descriptions omit a caveat that matters for how the proposal uses the work (items 2, 7, 9, 6); these are listed under the table.

Verification levels: FULL TEXT = the manuscript text was read; ABSTRACT = primary record and abstract only; INDEX LISTING; NOT FOUND; COULD NOT ACCESS.

## Factual errors and omissions noticed in the reviews

1. **Out-of-date title (red-team review).** arXiv:2610.09142 is cited as "Finding Side-Effect Loopholes in Verifiable Rewards". That was the v2 title (16 Oct 2026). The current v3 title (16 Nov 2026) is "Finding Side-Effect Loopholes in AppWorld and WorkArena Verifiers", as the novelty review has it. Same paper.
2. **Physical-device precedent is narrower than the novelty review's wording (item 7).** In arXiv:2602.07787v2 each task runs in one environment only; 16 of 116 tasks run on phones; the phones are not rooted. The paper does not run the same tasks on emulator and phone. The real-device runs are new in v2, dated 16 Nov 2026.
3. **VeriCUA's AndroidWorld numbers use the native checker as gold (item 2).** The review's description is correct, but "false positives" and "wrong fails" there are disagreements with AndroidWorld's official evaluator. The review also places the AndroidWorld evaluation in the appendix; it is in the main text too.
4. **MobileJudgeBench's checker figures are an inset in an RL figure (item 9).** The 94.6 / 98.6 / 87.2 figures are real, but the paper treats the rule-based checker as the oracle and does not frame the comparison as a checker audit. Human labels come from trajectory review.
5. **"Silent Instrument Errors" concerns harness errors (item 6).** Its rank changes come from ungraded episodes, cost double counting and evaluator version changes on HAL and τ²-bench, not from end-state checkers accepting wrong states.
6. **Truncated title (novelty review).** SWE-Mutation's title ends "…in Software Engineering?".
7. **Label used as a title (red-team review).** "Ranking-inversion analysis — arXiv:2609.25173" is "Attack Success Rate Is Not a Number: On Measurement Validity in Agentic AI Security Evaluation".
8. **Citation links.** Several links in the novelty review resolve to mirror or unrelated domains. Every claim attached to them was confirmed against the primary record, so this affects link hygiene only.
9. **A correction that goes the other way.** The novelty review's statement that AgentRewardBench annotators could consult the environment is supported by the paper; the project's own drift scan (`05_NOVELTY/IDEA_F1S_drift_scan.md`, item 2: "trajectory review, no retained state") is the text that needs amending.

No fabricated record, wrong identifier, or wrong number was found in either review for the 18 items.
