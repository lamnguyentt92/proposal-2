# Red-team review of IDEA_F1R (devil's advocate)
- Scores 1–5: novelty, significance, depth, soundness potential, evaluation, clarity, venue fit
  - Basis of this review: reviewed 2026-11-20. Inputs read in full: `04_IDEAS/IDEA_F1R.md`, `05_NOVELTY/IDEA_F1_priorart_A.md`, `05_NOVELTY/IDEA_F1_priorart_B.md`. Repository evidence: `github.com/google-research/android_world` cloned this session at commit `55ddaf5` (23 Oct 2026); file paths below are relative to `android_world/` inside the repository. Status labels: **[code]** = read in the repository this session; **[mine]** = my own classification or argument built on that code (a judgement, not a measurement); **[card]** = taken from the idea card or prior-art reports, not re-verified. No experiment was run; every prediction about agent behaviour is a conjecture.
  - Novelty **3** — cross-task relations on agent runs were not found by either hunter, but on AndroidWorld the instrument is dominated by a simpler check built from the card's own steps 1–2 (see baseline), R2 collapses into R4 (already anticipated, and already shipped in the suite as the `*Verify` tasks), and R3 collapses into a single-run footprint check.
  - Significance **2** — the certified quantity is "some masked state difference after a composed run on about a fifth of the templates", not "share of wrong PASS verdicts on the benchmark".
  - Depth **2** — no result that outlives one benchmark version; the estimator algebra is disclaimed; the relations are textbook property classes.
  - Soundness potential **2** — the headline estimand is not identified: its value is set by how wide the noise mask is, and "wrong PASS" is not defined by the benchmark's own task text.
  - Evaluation **2** — the strongest baseline is missing, the claims have dead zones and low power, C4 has no outcome that counts against the paper.
  - Clarity **3** — the card is readable, but title ("certified lower bounds … of wrong PASS verdicts") and what is actually certified diverge.
  - Venue fit **3** — ICML 2027 has an Evaluation area and a Datasets/Evaluations/Benchmarks type **[card]**; a single-benchmark audit with a software-testing instrument is a weak fit unless a general finding is added.

- Likely reasons for rejection:
  1. **The instrument is dominated by "diff against the gold run", which the approach already builds.** Steps 1–2 give a state observer, closed-loop gold policies "per task and per composition", and a measured mask. With these, every single agent run can be compared with the gold end state (or gold diff) directly. Formal version **[mine]**: let `V = 1[m(s2) ≠ m(s0)]` be the R1 flag after legs T, T⁻¹, and `G_i = 1[m(Δ_agent,i) ∉ {m(Δ_gold,i)}]` the per-leg gold-diff flag (gold T⁻¹ replayed from the agent's actual mid-state where the second diff depends on the first). If masked diffs compose and the gold round trip is clean — which is exactly what the mask calibration in step 2a establishes — then `G_1 = G_2 = 0 ⇒ V = 0`, so `{V=1} ⊆ {G_1 ∨ G_2 = 1}`. Every R1 certificate is also a gold-diff certificate; gold-diff additionally names the leg (the card needs two annotators for that), works on native single-task runs, and needs no inverse. The inclusion is strict: R1 cannot see (i) errors inside the target entity that T⁻¹ erases (a note created with slightly wrong text and then deleted), (ii) compensating errors (leg 1 adds an extra row, leg 2 removes it), (iii) any template without an inverse. The card's baseline list has "hand-written expected-diff checks" and "raw diff without the measured mask", but not "gold-run diff with the measured mask". C3 needs gold runs for every compared template, so wherever C3 is evaluated the dominating baseline exists by construction.
  2. **Relation coverage on the target benchmark is small and sits where the shipped checkers are already strongest.** 25 of 116 templates (22%) take part in a clean in-suite inverse, forming about 11 relation families; 14 of those 25 already ship a before/after integrity check on the target table or directory. The weak checkers (file-exists, membership, on-screen state) mostly have no inverse. Details in the repository section.
  3. **No inverse pair can be run with the shipped harness.** Each task's `initialize_task` wipes and re-seeds its own app state and `tear_down` wipes it again (`task_evals/task_eval.py`, `common_validators/sqlite_validators.py`, `common_validators/file_validators.py`, `suite_utils.py::_run_task`) **[code]**. The second-leg checker depends on state captured in its own initialisation (`self.before`, `self.rows_to_delete` = the rows it inserted itself; `_validate_initial_state` raises otherwise). A composed run therefore needs new initialisation and modified verifier code for every second leg. "The checker passed both legs … with no reading of verifier code" does not hold; the audited object becomes the authors' modified checker on an authors' composite task, not the AndroidWorld verdict.
  4. **"Violation" is not "wrong PASS".** AndroidWorld goal templates state a postcondition and no frame condition (`task_metadata.json`) **[code]**. A leftover draft, a search-history row or a second empty note does not make the verdict wrong under the benchmark's own specification. Deciding which differences matter is a per-task human judgement — the "per-task expected diff" and "human label" the key insight claims to avoid. Step 4 already brings two annotators back for attribution and severity.
  5. **The mask decides the headline number.** A mask measured from scripted round trips learns the residue of one UI path. Agents take other paths (search instead of scroll, another menu, a mis-tap and back, a permission dialog), which write other residue: recents, search suggestions, `sqlite_sequence`, WAL files, last-opened preferences, MediaStore rows, thumbnails, clipboard, learned keyboard words. "Held-out gold runs flagged ≤ 2%" validates the mask only on the gold path distribution. Narrow mask → C1 can be met by benign residue alone. Class-level mask (all preferences, all caches) → no longer "measured", and it hides the real class "agent changed an app setting". "Planted unrequested writes flagged ≥ 90%" is circular: the authors plant where the mask does not reach.
  6. **Composed runs are another distribution, and conditioning on two passes selects the easy cases.** Leg 2 starts from an agent-produced state with a non-home foreground, not from the seeded state. P(both pass) ≈ p², so weak agents and hard templates drop out — the cells where a lucky pass after much stray activity is most plausible **[mine]**. The inverse-eligible templates are short CRUD and toggle tasks (complexity 1–3.4 in the code); the hard templates (`MarkorMergeNotes` 7.8, `RetroPlaylistDuration`, `OsmAndTrack`, browser games, all 25 information-retrieval tasks) have no inverse. The bound cannot be carried to the 116-task score, and a lower bound `q` on compositions gives only `max(p1, p2) ≥ q/2` per leg.
  7. **C4 cannot inform.** The checkers are deterministic predicates (`is_successful` methods) **[code]**. A real false pass exists only where the checker is blind to that instance, i.e. in a sensitivity-0 cell, which the card excludes as non-estimable; in sensitivity-1 cells the predicted count is 0. Intermediate sensitivity comes only from mixing seeds inside a cell — e.g. `utils/fuzzy_match_lib.py` accepts `difflib` ratio ≥ 0.9, so "near-miss value" sensitivity is whatever edit sizes the authors choose to seed. The prediction is a function of the seeding recipe. And "either outcome is reportable" means no outcome counts against the paper.
  8. **Benchmark maintenance.** The likely product is a list of unframed checkers in one suite. The repository already contains the repair pattern (`validate_rows_addition_integrity`, `validate_rows_removal_integrity`, and `MarkorDeleteNewestNote` comparing the other files' names and change times) and a settings-wide before/after reader with a hand-declared mask (`env/adb_utils.py::get_all_settings`, `_post_process_settings`) **[code]**. Extending these to file-based tasks is a small upstream patch. The motivating finding (side effects among passes, differing by agent) is already published for tool-use agents (SABench, AgentRelBench; **[card]**).
  9. **Power.** About 11 relation families → cluster-robust intervals have about 11 effective units. A lower bound above 3% needs violations spread over most families at an observed rate of roughly 5% or more; the pre-specified negative (upper bound below 1%) needs on the order of 300 passed compositions with zero violations per agent before clustering. The most likely outcome, 1–3% or wide intervals, matches neither pre-specified result.

- Strongest baseline a referee will demand:
  - **Single-run whole-state frame check against gold**, using the same observer and the same mask: for every agent run on all 116 native templates, flag when the masked diff from the start state is not among the masked diffs of K gold runs of the same instance. It needs nothing beyond steps 1–2, no composition, and it localises the fault.
  - Its policy-free variant: **footprint rule from declared metadata** — every task declares `app_names`, and the SQLite families carry the expected rows in `params[ROW_OBJECTS]` **[code]**; flag any change outside the declared apps' data plus the expected rows. This is the "single whole-state frame check per task" that arXiv:2610.09142 lists as future work **[card]**. R3 (commutation of disjoint-app tasks) is equivalent to this rule applied to each run separately, so R3 adds no detection power.
  - Next: patched checkers (the integrity pattern extended to file, contact, SMS and playlist tasks) re-grading all retained passes; then the state-reading LLM verifier already listed in the card.
  - The paper must report **R1-only true detections** (flagged by R1, not by the gold diff, confirmed by blind adjudication). The inclusion argument predicts zero.

- Killer experiment:
  - **Paired comparison on the pilot (the card's ~15 pairs), same runs, three instruments:** R1 flag, per-leg gold-diff flag, blind severity label (change to user data outside the requested entity vs benign residue). Outcomes that end the idea in its present form — and my expectation for each, as conjecture:
    1. R1-only true detections = 0 → the metamorphic instrument adds nothing over the gold diff. Expected, because it follows from the inclusion argument unless masked diffs fail to compose.
    2. After removing flags graded as residue, the lower bound on the violation rate among passed compositions is below 3% (likely below 1%) for the strong agents → C1 fails in substance. Expected, because 14 of the 25 eligible templates already have in-table integrity checks and the rest are one-tap toggles and simple file operations.
    3. At least half of the raw flags are path-dependent residue absent from the gold-path mask → the mask is not transferable.
  - **Cheaper, agent-free pre-test (run first):** for each app script three *correct* round trips along different UI routes (search vs scroll, overflow menu vs long-press, one mis-tap plus back). Learn the mask on route A, measure false alarms on routes B and C. If the false-alarm rate on correct alternative routes exceeds about 10%, the validity precondition fails before any agent is run. I expect this to come out negative for at least the calendar, Markor and file-manager apps.

- Boundary cases or counterexamples (formal ideas):
  - **C1 (prevalence).** *Vacuous* when the mask is calibrated on one gold route: the rate is driven by route-dependent residue and the bound can exceed 3% with zero wrong verdicts. *Fails* when the mask is widened to key classes, or when the eligible sub-suite is integrity-checked and easy (rate → 0). *Uninterpretable* at 1–3%. *Counterexample to "certified wrong PASS"*: agent creates the requested Markor note and also leaves an empty `untitled.md`; `MarkorCreateNote` passes (file exists, content matches); the task text does not forbid extra files; the certificate certifies an extra file, not a wrong verdict. *Counterexample to completeness*: note content at similarity 0.9–1.0 passes the checker and is erased by the delete leg — invisible to R1, visible to a gold diff.
  - **C2 (differential error).** *Vacuous* at floor rates (no variance for the mixed model; about 11 template clusters). "Rescoring changes the order of at least one pair" is met by noise whenever two agents are within one or two runs of each other; without a rank-stability null (bootstrap over runs) the criterion is always met. The rescored quantity is a composite metric on 22% of the templates, not the AndroidWorld ranking. The direction of the finding is already established for tool-use agents **[card]**.
  - **C3 (existence is not prevalence).** *Tautological*: prevalence = (agent propensity to commit the fault) × (checker blindness); the kill rate measures only the second factor, so low correlation follows whenever propensity varies by template, and high correlation would require homogeneous propensity. *Underpowered*: with 11–25 templates, a Spearman interval is about ±0.5, so ρ < 0.4 cannot be told from ρ = 0.8. *Degenerate*: per-template kill rates are near 0/1 (identical verdicts in 107 of 109 template-by-edit groups in arXiv:2610.09142 **[card]**) and agent violation rates are mostly 0 → ties dominate. The claim is also phrased as an absence of association, which an underpowered design cannot support.
  - **C4 (coupling test).** *Vacuous* when (a) the audit interval is wide — at a 2% base rate, 200 audited passes give roughly 0.5%–5%, so almost any prediction lies inside; (b) all real false passes fall in sensitivity-0 cells, are excluded as non-estimable, and the prediction covers only cells that cannot contain a false pass; (c) within-cell sensitivity is set by the seeded magnitude distribution (fuzzy threshold 0.9), so agreement can be tuned and disagreement only reflects the recipe. It also needs the number of true failures per mode among each agent's FAIL verdicts — a human labelling of failed runs plus a correction for wrong FAILs — which contradicts "without labelling".
  - **R2 (idempotence).** The second run *is* the pre-satisfied-goal case (R4, anticipated by OpenReview i7FGehiANA **[card]**). AndroidWorld already ships it for seven tasks (`System{Wifi,Bluetooth}Turn{On,Off}Verify`, `SystemBrightness{Max,Min}Verify`, `ClockStopWatchPausedVerify`) **[code]**.
  - **When relations are genuinely needed (gold end state unavailable or not unique).** (a) Goals with many valid end states: `RetroPlaylistDuration` (any song subset totalling 45–50 min), `ExpenseDeleteDuplicates` (either copy may go; the checker has an `or`), `CameraTakePhoto` (timestamped file name), `SimpleDrawProCreateDrawing` (arbitrary pixels) **[code]**. For these a start-state reference is unique where a gold end state is not — but none has an in-suite inverse except `SimpleDrawProCreateDrawing` via `FilesDeleteFile` on `Pictures`, and a value-agnostic footprint check handles them without relations. (b) Environments that cannot be reset or scripted (live services) but offer reversible operations: there a round trip may be the only label-free reference. That regime is not the emulator setting the card targets. On AndroidWorld the set {gold not unique} ∩ {inverse exists} is about one template **[mine]**.

- What would make this a clear accept:
  1. **Beat the dominating baseline or adopt it.** Either show confirmed R1-only detections against the masked gold diff on the same runs, or make the single-run whole-state frame check the main instrument (all 116 templates, native runs, retained post-state) and keep relations as a secondary reference for goals whose valid end state is not unique.
  2. **Find the regime where relations are necessary** — tasks with many valid end states and a well-defined inverse, or environments that cannot be reset or scripted — and show the instrument there. Check relation coverage and checker style in the second mobile benchmark and the safety benchmarks *before* committing; require at least about 30 relation families and at least half of the suite covered.
  3. **Fix the estimand in advance:** "change to user data outside the requested entity", defined by rule, with residue classes excluded by rule and reported separately; title and claims say "unrequested effect among passes", not "wrong PASS", unless the benchmark text states a frame condition.
  4. **Validate the mask across routes:** false-alarm rate on several distinct correct routes per app and on human demonstrations, not only on held-out replays of the gold route.
  5. **Replace C3 and C4 with claims that can fail:** C3 as a decomposition (propensity × blindness) with enough templates to estimate it; C4 only for graders with non-degenerate sensitivity (fuzzy or LLM-based), with the seeding distribution fixed before the audit and an audit large enough that a wrong prediction would fall outside the interval.
  6. **Report on the benchmark's own distribution:** prevalence on native single-task passes for all agents, with a bootstrap null for rank changes; composed runs only as a robustness section, with the two-pass selection effect quantified.
  7. **One finding that generalises:** for example, a measured relationship across several benchmarks between checker style (postcondition-only vs integrity-checked) and unrequested-effect prevalence, a characterisation of what round-trip relations can and cannot detect (the erased-footprint blind spot) with a tightness result, or automatic synthesis of inverse tasks that lifts coverage above half of a suite.
